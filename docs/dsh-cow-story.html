远程黑窗口，

10 / 看得见屏幕API 之外的最后一公里

看得见屏幕，
才做得了最后一公里。

API 和命令行能处理文件、系统和服务，但很多工作只存在于图形界面：老 ERP、设计软件、U 盾弹窗、只有 GUI 的测试工具。本地 DSH 可以接入 Computer Use：看屏幕、点按钮、填表单，再截图复核。

本地桌面 / 真实工作面

已登录的 ERP 和原生客户端不是重新登录一个云桌面，而是员工正在用的那套系统。
授权软件、字体、插件、测试工具本地装好、本地授权；很多工具根本装不到云上。
USB 设备、共享盘、双屏U 盾、税盘、数位板、映射盘，都在本机可用。
真实分辨率、颜色和系统弹窗不是远程缩放过的画面，也不是一个精简的虚拟桌面。

11 / 最高权限能看见，也能误操作

屏幕和鼠标，
是最高权限。

Computer Use 不是默认安全能力：它看得见密码，也点得动删除。要把它做成可控的执行层，而不是无人值守的万能手。

会话 / 01
必须登录的交互式桌面

锁屏、服务会话、Session 0 看不到桌面；macOS 还要屏幕录制和辅助功能权限。

应用 / 02
先白名单，再动手

只操作批准的应用；默认不碰支付、密码框、系统设置和未知弹窗。

动作 / 03
破坏性动作要人确认

删除、提交、发送、付款、审批，必须停下来问人；还要有随时可停的热键。

屏幕 / 04
截图可能带秘密

截图会看到客户资料、Token、聊天记录；要脱敏、限时保留，尽量本地处理。

注入 / 05
屏幕内容是“不可信输入”

网页、邮件、文档里的字不能当成命令；屏幕上的提示注入不能直接执行。

并发 / 06
一个桌面，一个操作者

多个 Agent 同时动鼠标会互相抢焦点；员工正在用时，员工优先。

能看见，不等于该动手；能动手，不等于没人看着。

12 / 分工人做决定，数字员工做执行

人做决定，
数字员工做执行。

不是让 AI 代替人，而是给每个人多一个能干的自己。人保留判断、授权和责任，数字员工承担重复、跨机器、需要守着的工作。

员工负责

定目标这件事要做成什么样，员工说了算。
做判断拿不准、有风险、要拍板的事，人来决定。
给授权能动哪些文件、能不能对外发送，员工来定。
担责任最终结果由员工和公司承担，不是数字员工。

数字员工负责

接活把一件事放进自己的待办，按节奏做。
干活在本机用软件、文件、命令行，把事做完。
回话干完主动回来交结果，不用人一直催。
请示拿不准就回来问，不自己乱来。

不是让 AI 代替人，而是让人多一个能干的自己。

文件夹 / 01

默认只在员工的工作目录里动手，不碰别人的资料。

请示 / 02
重要的事先请示

账号 / 03
账号不离开电脑

信任 / 04
只跟信得过的同事合作

只连公司里可信的数字员工，陌生的数字员工不接活。

记录 / 05

追查 / 06

19 / 结构红利不是功能，是结构

结构变了，
好处会自己长出来。

这些不是功能清单，是“数字员工在电脑上”带来的结构红利；很多在传统集中式 Agent 里做不到。

零迁移
不用搬家不用重装软件、迁数据、重建权限；装上数字员工就开始。
一人多数字员工
一个人就是一支小队办公室、家里、测试机各有一个数字员工；一台坏了，别的还在。
账号不扩散
账号留在电脑上不用把公司账号复制到中心；一处出事，不会处处出事。
组织即权限
组织架构就是权限图谁向谁汇报、谁给谁派活，天然就是规则，不用两两配权限。
没有中心
断网也能干活没有中心调度；网络断了，本地的工作还能继续。
旧设备
老电脑继续用Mac、Windows、Linux、授权软件、外设，都不用为了 AI 重建。

这些优势，来自“数字员工在电脑上”这个结构，不是某个功能。

20 / 实际例子三种系统，一套组织

引擎组要过一次新特性，
三套系统都要跑。

Windows、Linux、macOS，各有不同的编译和测试机；没有互联网，大量样本在本机，有些机器还要用共享文件夹，密码已经配在电脑上。

其他方案卡在哪

云端 CI / 云 Agent样本太大传不上去；没有外网；引擎工具和平台硬件也不在云上。
SSH / 跳板机登录后看不到映射盘、钥匙串和桌面测试工具；共享目录密码还得复制给 Agent。
中央 Agent 平台要给每台机器装 Agent、配访问凭据，变成一次新的平台迁移。
人工搬来搬去三套系统来回切，构建、日志、截图版本容易对不上。

COW 怎么跑

引擎负责人 · 数字员工派活 / 汇总
Windows 构建机D3D12 · 共享盘
Linux 测试机Vulkan · 200 用例
macOS 验证机Metal · 截图对比
本机编译本机跑用例共享盘用本机凭据只回传日志 / 结果样本不搬家
前提：机器之间至少能内网互通；共享盘要对本机运行 DSH 的用户可见。有的测试工具只有 GUI，Computer Use 可看屏幕操作；高风险动作仍由人确认。

不是把三台机器搬上云，而是让每台机器就地有一个数字员工。

21 / 实际例子钱和税，不能离开工位

月结那几天，
财务的电脑不能离开工位。

税盘、银行 U 盾、ERP 客户端、Excel 宏和共享盘密码，全在财务电脑上；月底要开票、对账、报税，还要有人复核。

其他方案卡在哪

云端 RPA / AgentU 盾和税盘插在本地，云上看不见；凭证和银行数据也不能上传。
SSH / 跳板机只有命令行窗口；ERP 页面、浏览器登录、U 盾弹窗都看不见，凭据还得复制。
中央 Agent 平台要把税盘、银行 U 盾、财务账号集中到平台，合规和审计先过不了。
人工导出再确认导出、截图、邮件确认来回跑，月底最容易版本错。

COW 怎么跑

财务主管 · 数字员工派活 / 复核
应付机ERP · 共享盘
应收机开票 · 对账
税务机税盘 · U 盾
本机开票本机对账本机报税重要动作请示只回传结果
U 盾、税盘、ERP 和共享盘凭据都留在本机；U 盾/税盘由人确认，Computer Use 只填单、核对、回传；主管在组织树里复核。

钱和税，不该为了自动化离开财务电脑。

23 / 智能体组织传统组织的下一层

这不是工具升级，
是“智能体组织”。

智能体组织：以每台电脑为单位配置数字员工，数字员工按公司上下级关系手工组织；人负责目标、判断和授权，数字员工负责执行、记忆和回话。

01
信息化把工作记录进系统
02
数字化把流程搬到线上
03
智能化给个人配 AI 助手
04
智能体组织每台电脑一个数字员工
一台电脑一个数字员工上下级手工接人负责授权能力留在工位

传统组织的智能化转型，不是换一套系统，而是给每台电脑加一个能动手的数字员工。

24 / 怎么管人、数字员工、工位

智能体组织，怎么管？

管理对象从“人和系统”，变成“人、数字员工、工位”。不是多一套监控，而是多一层可控的执行体。

01 / 归属

员工管理自己的数字员工

每台电脑一个数字员工；员工可以决定谁能派活、能碰什么，不想要了可以停掉、收回权限。

02 / 能见度

组织看得见，但不偷看

公司看得到谁在岗、谁在忙、谁借网；员工自己的文件内容不被集中上传。

03 / 权限

权限跟着组织走

谁能给谁派活、谁给谁审批，按汇报线来；不用给每对电脑单独配。

04 / 离场

来去都能收得回

员工离职或换岗，逐台收回数字员工的权限；不是把一把万能钥匙留在系统里。

控制权给员工，能见度给组织，边界给制度。

25 / 待办还没做完

还没做好的事，
也说清楚。

这是一份待办清单，不是完成态。先把边界做对，再谈规模。

01 / 跨网络
两台不同网络的电脑还不能直接见面现在要靠隧道或中继；公网直达还没做。
02 / 身份
员工身份与钥匙现在用共享密码，还没接公司账号、临时钥匙和自动作废。
03 / 细粒度
细到工具的权限现在只能管文件夹和网站，还没细到“这个软件能做几步”。
04 / 借网
有些软件不认借网借网主要帮网页类请求；别的软件可能还是上不了。
05 / 发现
隔了网络就找不到同一个办公室网络能自己找；隔开就得手动填地址。
06 / 恢复
断电重启后的恢复与审计现在靠每件事自己的记录；公司级的记录、调度和恢复还没做。

先把边界做对，再谈规模。

26 / 开始从一个人、一个团队开始
先给一个团队，
配上数字员工。

不用先建大平台。选一个岗位、装一台电脑、交一件真活；跑通了，再扩到团队。

01
选一个岗位财务、研发、设计，找一个“只在某台电脑上能干”的活。
02
装一个数字员工在那台电脑上装 DSH，不动原有软件和账号。
03
交一件真活派一件小事，看它接活、干活、回话、请示。
04
再扩到团队把同事的数字员工接进同一棵组织树。

未来的公司，不是每个公司一个超级 Agent，而是每台电脑一个数字员工，数字员工手工接成公司。
